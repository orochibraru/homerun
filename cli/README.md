# Homerun CLI

A typed CLI for Homerun's REST API, built on
[`openapi-fetch`](https://openapi-ts.dev/openapi-fetch/) against the spec
served at `/api/v1/openapi.json` — see the main app's `$lib/openapi/`. This
is what the "Once OpenAPI specs are generated we can build the CLI" TODO
item meant: the types in `src/generated/openapi-types.ts` are generated by
`openapi-typescript` straight from a running instance's real spec, so the
client is compile-time checked against the actual API shape, not a
hand-maintained guess.

## Running it

```
bun install
HOMERUN_BASE_URL=https://your-instance.example.com \
HOMERUN_API_KEY=<a key from the app's own API-key creation flow> \
bun run src/index.ts services list
```

Or compiled to a standalone binary:

```
bun run build
./dist/homerun services list
```

`--base-url`/`--api-key` flags work the same as the env vars, and take
precedence.

## Commands

```
homerun services list [--json]
homerun services get <id>
homerun services deploy <id>
homerun services start <id>
homerun services stop <id>
homerun services restart <id>
homerun projects list [--json]
homerun templates list [--json]
```

`list` without `--json` prints a plain text table; every other command
prints the raw JSON response. There's no `create`/`update`/`delete` yet —
out of scope for this first pass, straightforward to add the same way
(`commands.ts` already has the `unwrap()` helper every command uses).

## Regenerating the types

```
HOMERUN_BASE_URL=https://your-instance.example.com bun run generate
```

Re-fetches `/api/v1/openapi.json` from a running instance and regenerates
`src/generated/openapi-types.ts`. Do this after any REST API route changes
in the main app (`src/routes/api/v1/**`) — the checked-in types will
silently go stale otherwise (`openapi-fetch` itself won't catch a stale-spec
mismatch at compile time, since it only ever sees whatever `paths` type you
hand it).

## What's verified vs. not

**Verified live, full round trip**: the main app's `/api/v1/openapi.json`
is a real, valid OpenAPI 3.1 document (parsed successfully by
`openapi-typescript`, not just eyeballed); a throwaway account + real API
key (against the isolated `homerun_test` database, never the maintainer's
real one — see the main repo's qa conventions) drove every command in this
README against a real Docker daemon: `services list`, `get`, `deploy`
(real `nginx:alpine` pull+create+start), `start`, `stop`, `restart` — all
succeeded and returned correctly-typed responses. The 401 path was also
verified (a bad API key fails cleanly with a readable error, not a crash).

The compiled binary (`bun run build` → `./dist/homerun`) was also smoke-tested and behaves identically to running from source.
